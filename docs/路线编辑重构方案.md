# 路线编辑功能重构方案

## 1. 当前问题分析

### 1.1 架构问题
- **页面跳转复杂**：`route` → `my-route` → `route`，形成循环导航
- **数据传递不可靠**：依赖 `eventChannel` 或全局变量，热重载时容易丢失
- **职责不清晰**：`route` 和 `my-route` 功能重叠，数据流向混乱

### 1.2 用户体验问题
- 频繁页面跳转，加载时间长
- 返回后需要重新渲染，可能有闪烁
- 编辑结果应用不可靠，用户困惑

---

## 2. 重构目标

### 2.1 架构目标
- **单一页面**：合并 `route` 和 `my-route` 为单一页面
- **模式切换**：通过 `editMode` 状态切换预览/编辑模式
- **数据统一**：共享同一份路线数据，避免传递问题

### 2.2 用户体验目标
- 无缝切换预览和编辑模式
- 编辑结果实时预览
- 更流畅的交互体验

---

## 3. 技术方案

### 3.1 页面结构

```
route 页面（单一页面）
├── 数据层
│   ├── routeData: 路线数据（daySections, routeShops 等）
│   ├── editMode: 'preview' | 'edit' 当前模式
│   └── editState: 编辑态临时状态（拖拽、选中等）
├── 业务逻辑层
│   ├── route-behavior: 路线核心逻辑（加载、保存、计算）
│   ├── route-edit-behavior: 编辑逻辑（拖拽、添加、删除）
│   └── route-preview-behavior: 预览逻辑（地图、卡片展示）
└── 视图层
    ├── route.wxml: 预览模式布局
    ├── route-edit.wxml: 编辑模式布局（原 my-route.wxml）
    └── route.wxss / route-edit.wxss: 样式
```

### 3.2 状态管理

```javascript
// route.js data
{
  // 模式控制
  editMode: 'preview', // 'preview' | 'edit'
  
  // 路线数据（预览和编辑共享）
  routeData: {
    id: '',
    title: '',
    daySections: [],
    routeShops: []
  },
  
  // 预览模式状态
  previewState: {
    currentTab: 0,
    mapCenter: {},
    // ...
  },
  
  // 编辑模式状态
  editState: {
    dragging: false,
    selectedDayIndex: 0,
    // ...
  }
}
```

### 3.3 模式切换

```javascript
// 切换到编辑模式
switchToEditMode() {
  this.setData({
    editMode: 'edit',
    // 保留当前路线数据，直接进入编辑
  })
},

// 切换到预览模式
switchToPreviewMode() {
  // 用编辑后的数据重新生成预览状态
  const previewState = this.buildPreviewStateFromRoute(this.data.routeData)
  this.setData({
    editMode: 'preview',
    ...previewState
  })
}
```

### 3.4 文件组织

#### 现有文件
- `route.js` - 路线预览页逻辑
- `route.wxml` - 路线预览页布局
- `my-route.js` - 路线编辑页逻辑
- `my-route.wxml` - 路线编辑页布局

#### 重构后文件
- `route.js` - 主页面逻辑（合并原 route.js 和 my-route.js）
- `route.wxml` - 主页面布局（包含 preview 和 edit 两个模板）
- `route.json` - 页面配置
- `route.wxss` - 页面样式（合并原两个页面的样式）

#### Behavior 拆分
- `route-behavior.js` - 路线核心逻辑（加载、保存、计算）
- `route-edit-behavior.js` - 编辑逻辑（拖拽、添加、删除）
- `route-preview-behavior.js` - 预览逻辑（地图、卡片展示）
- `route-map-behavior.js` - 地图相关逻辑
- `route-place-behavior.js` - 地点选择逻辑

## 5. 风险和注意事项

### 5.1 技术风险
- **代码合并冲突**：两个页面逻辑复杂，合并时可能有冲突
- **性能问题**：单一页面代码量大，需注意性能优化
- **状态管理复杂**：预览和编辑状态切换需仔细设计

### 5.2 产品风险
- **用户习惯改变**：原有页面跳转流程改变，需评估用户接受度
- **功能遗漏**：合并过程中可能遗漏某些功能

### 5.3 缓解措施
- 分阶段实施，每阶段可独立测试和回滚
- 保留原有页面作为备份，灰度发布
- 充分的单元测试和集成测试
