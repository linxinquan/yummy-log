## 1. 文档概览

本文档是 Yummy 小程序（觅食图）中**路线规划、地图渲染、导航**三大功能模块的完整技术文档。

### 1.1 涉及的核心功能

| 功能 | 说明 |
|------|------|
| **路线规划** | 基于贪心最近邻算法或保持原顺序，对多天多地点做路径优化 |
| **地图渲染** | 调用腾讯地图 API 绘制真实驾车/步行/骑行/公交路线，失败降级为模拟正弦路线 |
| **逐站导览** | 进入导览模式后逐站导航，支持"已到达"状态切换 |
| **出行方式切换** | 支持步行/骑行/公交/驾车四种出行方式的全局和逐段切换 |
| **交通偏好** | 全局短距离/长距离交通偏好设置，保存到 localStorage |
| **智能重排** | 从"我的路线"页对已有路线触发重新规划 |

### 1.2 关键术语

| 术语 | 含义 |
|------|------|
| **出行方式 (travelMode)** | 步行(walk)、骑行(ride)、公共交通(transit)、驾车(drive) |
| **交通元数据 (travelMeta)** | 包含出行方式、距离文本、时间文本、图标等结构化信息 |
| **贪心最近邻** | 路线规划算法：从起点出发，每步选最近的下一个未访问点 |
| **地图折线 (polyline)** | 腾讯地图 API 返回的压缩坐标串，或模拟生成的正弦弯曲路线 |
| **dayStartPoint** | 每天路线的起点坐标，可以是当前位置、前一天终点或搜索地点 |
| **routeDaySections** | 按天分组的路线数据结构，每段包含 items 数组 |

## 4. 出行方式系统

### 4.1 出行方式枚举 (`travel.js` → `MODE_CONFIG`)

```javascript
const MODE_CONFIG = {
  walk:    { key: 'walk',    label: '步行',     shortLabel: '步', minutesPerKm: 12 },
  ride:    { key: 'ride',    label: '骑行',     shortLabel: '骑', minutesPerKm: 4  },
  transit: { key: 'transit', label: '公共交通', shortLabel: '公', minutesPerKm: 5  },
  bus:     { key: 'bus',     label: '公交',     shortLabel: '公', minutesPerKm: 6  }, // ⚠️ 旧版兼容
  drive:   { key: 'drive',   label: '驾车',     shortLabel: '车', minutesPerKm: 3  },
}
```

**展示顺序**: `MODE_ORDER = ['walk', 'ride', 'transit', 'drive']`（弹窗只展示 4 大类）

**bus → transit 归一化**: `normalizeTransportMode('bus')` → `'transit'`（`bus` 为旧数据兼容）

### 4.2 距离与出行方式偏好

| 距离范围 | 默认出行方式 | 偏好存储键 |
|---------|------------|-----------|
| < 1000m (短距离) | `walk` (步行) | `shortDistanceMode` |
| ≥ 1000m (长距离) | `drive` (驾车) | `longDistanceMode` |

偏好存储在 `globalTransportPreferences`（`wx.setStorageSync`），可在路线基础信息页修改。

### 4.3 腾讯地图 API 映射 (`map-config.js`)

| 内部 key | 腾讯 API 模式 | API 端点 | 地图颜色 |
|---------|-------------|---------|---------|
| `walk` | `walking` | `.../direction/v1/walking/` | `#4CAF50` 绿 |
| `ride` | `bicycling` | `.../direction/v1/bicycling/` | `#9C27B0` 紫 |
| `transit` | `transit` | `.../direction/v1/transit/` | `#FF9800` 橙 |
| `drive` | `driving` | `.../direction/v1/driving/` | `#2196F3` 蓝 |

### 4.4 出行方式链表

```
设置入口：
  ├── 全局默认（travelMode）           → route.js data.travelMode = 'drive'
  ├── 路线页面顶部切换                   → onSelectMode(e)  → 整条路线统一变更
  ├── 逐段交通弹窗                      → openTransportSheet()  → 单一地点出行方式变更
  └── 基础信息编辑（交通偏好）           → route-basic-edit.js  → 全局短/长距离偏好

应用方式：
  ├── applyTravelMeta(item, mode)       → 生成 travelMeta 元数据对象
  ├── buildTravelOptions(distance)      → 生成弹窗选项列表
  └── getPreferredTravelMode(distance)  → 根据距离和偏好自动推断
```

## 7. 架构审查 ⭐

### 7.1 总体评价

当前架构采用了 **Behavior 模式** 来让 `route.js`（路线规划页）和 `my-route.js`（我的路线详情页）共享代码，整体方向是正确的。但两页之间存在**大量逻辑重复**和**数据模型不一致**的问题，导致维护成本高、功能表现不统一。

| 维度 | 评分 | 说明 |
|------|------|------|
| 模块划分 | ⭐⭐⭐ | Behavior 方案合理，但 my-route.js 过于庞大（1898 行）未拆分 |
| 代码复用 | ⭐⭐ | Behavior 框架搭好了，但 my-route.js 自己又实现了一遍相同逻辑 |
| 数据一致性 | ⭐⭐ | routeShops vs daySections 两种主数据结构，转换逻辑分散 |
| 错误处理 | ⭐⭐ | API 有降级方案，但多处存在未定义方法调用 |
| 可测试性 | ⭐ | 逻辑与 UI 强耦合，无单元测试 |

### 7.2 架构优点

1. **Behavior 复用模式正确**：`route.js` 通过 5 个 Behavior 获得地图渲染、预览、编辑、导览、地点交互能力，避免了单文件膨胀
2. **配置分离**：`map-config.js` 将地图常量（颜色、API 映射、缩放阈值）集中管理
3. **出行方式抽象**：`travel.js` 封装了出行方式的配置、归一化、元数据生成
4. **API 降级策略**：腾讯地图 API 失败时自动降级到模拟正弦路线
5. **路线缓存**：`_routeCache` 按起点+模式缓存折线，避免重复请求

### 7.3 🔴 严重问题

#### 问题 1：`_planAndAnnotate` 方法未定义（运行时崩溃）

**文件**：`route.js:380,402`、`route-edit-behavior.js:104`

```javascript
// route.js:380 — onToggleCandidate 中调用
const routeShops = this._planAndAnnotate(selectedShops)
// route.js:402 — onToggleSelectAll 中调用
const routeShops = this._planAndAnnotate(updated)
// route-edit-behavior.js:104 — onOptimizeRoute 中调用

```

**影响**：自定义选择模式下，勾选/取消勾选单个地点、全选/取消全选、以及优化路线功能均会**直接报错崩溃**。

**根因**：该方法在任何 Behavior 或 Page 定义中都找不到定义。

#### 问题 2：`my-route.js` 地图渲染只用直连线，未调用真实路线 API

**文件**：`my-route.js:730-786` vs `route-map-behavior.js:20-169`

| 对比维度 | route.js（规划页） | my-route.js（详情页） |
|---------|-------------------|----------------------|
| 路线来源 | 腾讯地图 API → 真实道路 | **直线连接 markers** |
| 降级方案 | 模拟正弦曲线 | 无 |
| 出行方式染色 | 根据 mode 切换颜色 | 固定 `#47BFFE` |
| 缓存 | 有 `_routeCache` | 无缓存 |

**影响**：我的路线详情页看到的路线永远是折线图，不是真实道路，用户体验与规划页不一致。

- `guide-detail.js` 页面已修复，现在调用真实路线API（参考第15节）
- `my-route.js` 页面本次主要修复了地图聚焦问题，路线API调用问题待后续修复

#### 问题 3：`markerIcons` 未导入（运行时崩溃）

**文件**：`my-route.js:742`

```javascript

```

但 `my-route.js` 顶部从未 `require` 或 `import` `markerIcons` 模块！这会导致地图模式初始化和更新时直接报错。

### 7.4 🟡 设计问题

#### 问题 4：两页数据模型不一致

```
route.js:     routeShops (扁平数组)  ⇄  routeDaySections (按天分组，展示用)
my-route.js:  daySections (按天分组)  → mapPreviewPlaces (扁平数组，展示用)
```

- `route.js` 以扁平 `routeShops` 为主数据，衍生 `routeDaySections`
- `my-route.js` 以嵌套 `daySections` 为主数据，衍生 `mapPreviewPlaces`
- 两边的转换逻辑散落在 `routeHelper.js`、`my-route.js`、各 Behavior 中
- **建议**：统一为 `daySections`（嵌套）作为唯一主数据结构，`routeShops` 改为派生

#### 问题 5：大量辅助函数在文件间重复定义

以下函数在 `routeHelper.js` 和 `my-route.js` 中**各有一份独立实现**：

| 函数 | routeHelper.js | my-route.js |
|------|:---:|:---:|
| `buildDayLabel` | ✓ (L141) | ✓ (L46) |
| `buildTabs` | ✓ (L173) | ✓ (L53) |
| `buildSummaryText` | ✓ (L182) | ✓ (L253) |
| `getCityInfo` | ✓ (L189) | ✓ (L267) |
| `getPreviewIndexByDay` | ✓ (L251) | ✓ (L231) |
| `getDayIndexByPreview` | ✗ | ✓ (L241) |
| `buildLegacyRouteData` | ✓ (L200) | ✓ (L197) |
| `CITY_PRESETS` | ✓ (L13) | ✓ (L18) |
| `flattenDaySections` | ✗ | ✓ (L220) |

**此外**，`getDayIndexByPreview` 在 `route-preview-behavior.js:8` 中还有第三份实现。

**建议**：统一归入 `routeHelper.js`，其他文件只 import。

#### 问题 6：`my-route.js` 过于庞大（1898 行）

该文件包含：UI 状态管理 + 数据转换 + 拖拽排序 + 左滑删除 + 地点选择器 + 交通方式弹窗 + 导航弹窗 + 地点简介 + 保存/加载 + 分享，相当于一个"上帝对象"。

**建议**：像 `route.js` 一样拆分成多个 Behavior，或将纯逻辑抽到 utils 层。

#### 问题 7："智能重排"实际未执行重新排序

**文件**：`my-route.js:1137`

```javascript
const optimizedSections = syncDaySections(currentSections, this.data.cityInfo)
```

`syncDaySections()` 内部调用 `util.planRoute(rawItems, cityCenter, true)` — **`preserveOrder=true`**，意味着"智能规划"完全保留了原始顺序，与手动编辑后重新执行 `syncDaySections()` 效果完全相同。

**影响**：用户点击"智能规划"后，路线顺序没有任何变化。

#### 问题 8：逐段交通方式变更时错误地修改全局 travelMode （已解决）

**文件**：`route.js:504`

```javascript
// onConfirmTransportMode 中：
const nextData = {
  // ...
  travelMode: pendingTransportMode // 同时更新整条路线的默认交通方式
}
```

用户修改某一段的出行方式时（如从驾车改为步行），整条路线的默认方式也被改了，导致地图折线颜色错误切换、后续新增地点也继承了这个临时模式。

#### 问题 9：导航函数冗余

**文件**：`util.js`

// 把"按天分组"的路线拍平成普通数组，方便地图预览和统计
function flattenDaySections(daySections) {
  const flattened = []
  ;(daySections || []).forEach((day, dayIndex) => {
    ;(day.items || []).forEach((item, itemIndex) => {
      flattened.push({ ...item, dayIndex, itemIndex })
    })
  })
  return flattened
}

### 15.3 技术要点

#### 15.3.1 双坐标格式支持

地点坐标可能存在两种格式：
- 格式1: `{ lat, lng }`（新格式）
- 格式2: `{ latitude, longitude }`（旧格式）

修复中统一支持两种格式：
```javascript
const lat = currentPlace.lat !== undefined ? currentPlace.lat : currentPlace.latitude;
const lng = currentPlace.lng !== undefined ? currentPlace.lng : currentPlace.longitude;
```

#### 15.3.2 setData 同步更新特性

微信小程序 `setData` 是同步的，但视图层更新是异步的。需要确保 `setData` 完成后再执行依赖最新数据的逻辑，使用 `setTimeout` 确保执行顺序：

```javascript
this.setData({ currentMapDay: dayIndex }, () => {
  // setData 回调中执行后续逻辑
  setTimeout(() => {
    this.refreshMapPreview(dayIndex);
    this.updateMapData();
  }, 0);
});
```

fetchRealRoute(startLatLng, endLatLng, mode)

    // 处理路线数据
  })
  .catch(err => {
    // 降级处理
