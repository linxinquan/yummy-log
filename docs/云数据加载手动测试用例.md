# 云数据加载 — 手动测试用例

> 版本：v1.2  
> 更新日期：2026-06-24  
> 关联功能：微信云开发云端数据读写、用户登录、数据迁移、旧版假登录兼容

---

## 前提条件

- 微信开发者工具中开启**云开发模拟器**
- 准备两个微信测试号（设备 A / 设备 B），或先登录再清缓存模拟新设备
- 本地已存在一些打卡、想去、收藏数据（模拟老用户场景）

## 用例 10：旧版假登录兼容（版本升级）

| # | 测试动作 | 预期结果 | 关键代码路径 |
|---|---------|---------|-------------|
| 10.1 | **前置**：模拟旧版本数据，执行以下命令注入旧格式 `userInfo` | 本地缓存存在 `userInfo: { nickName: '测试', avatarUrl: 'xxx' }` **无** `_id` 和 `openid` | 手动注入 |
| 10.2 | 打开新版小程序 → 进入"我的"页 | `loadUserInfo()` 检测到旧格式（无 `_id`/`openid`）→ 清除 `userInfo` → 显示未登录状态；控制台输出 `[my] 检测到旧版假登录数据，已清除，需重新登录` | `my.js` loadUserInfo → `util.isCloudMode()` |
| 10.3 | 不登录 → 采集几条打卡数据 | 数据保存到本地缓存，`_isCloudMode()` 返回 `false`，走本地路径 | `checkinUtil.js` → `checkinRecords.js` |
| 10.4 | 点击"登录"→ 完成微信授权登录 | 调用云函数 `login`，返回带 `_id`、`openid` 的 `userInfo` 写入本地 | `my.js` onWechatLogin |
| 10.5 | 登录成功后弹窗"检测到本地数据"→ 点"立即同步" | 调用 `migration.migrateAll()`，本地数据逐条写入云端 | `my.js` syncLocalDataToCloud → `migration.js` |
| 10.6 | 退出登录 → 清除 `userInfo` | 再次进入"我的"页显示未登录；本地打卡数据保留 | `my.js` onLogout |
| 10.7 | 重新登录同账号 | 云端数据正常读取（打卡、想去、收藏、路线与之前一致） | 各 `xxxAsync` 函数 |
| 10.8 | 再次退出 → 清除本地全部缓存 → 用旧版假登录方式写回旧格式 `userInfo` → 打开新版 | 同 10.2，再次被检测清除，显示未登录 | `util.isCloudMode()` |

> **重点验证**：旧版假登录的 `userInfo` 没有 `_id`/`openid`，新版必须识别并清除，避免 `_isCloudMode()` 误判为已登录导致云操作静默失败。

## 路线云端同步现状说明

> ✅ **2026-06-24 确认**：`route.js`（`savePreviewRouteData` 第38-47行）和 `my-route.js`（`saveRouteToStorage` 第582-597行）**已实现云端同步**，路线保存时自动推送到云端。

## 测试优先级

| 优先级 | 用例 | 原因 |
|-------|------|------|
| **P0** | 1.1 ~ 1.4（登录）, 2.1 ~ 2.5（数据迁移）, 3.1 ~ 3.4（首页想去）, 5.1 ~ 5.2（打卡）, 10.1 ~ 10.3（旧版登录兼容） | 最核心的登录 + 数据迁移 + 读写链路 + 版本升级兼容 |
| **P1** | 2.6 ~ 2.9（迁移边界）, 6.1 ~ 6.4（收藏）, 4.1 ~ 4.4（想去页）, 8.1、8.2、8.6（路线列表/删除） | 功能性验证 |
| **P2** | 7.1 ~ 7.6（跨设备）, 9.1 ~ 9.5（异常）, 8.3 ~ 8.5、8.8、8.9（路线编辑/复制/发布）, 10.4 ~ 10.8（旧版登录后续场景） | 数据一致性和健壮性 |

> **P0 用例通过即可认为新增云端功能基本可用；P1/P2 用于验收完整性和健壮性。**
