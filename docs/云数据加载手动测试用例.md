# 云数据加载 — 手动测试用例

> 版本：v1.0  
> 更新日期：2026-06-23  
> 关联功能：微信云开发云端数据读写、用户登录、数据迁移

---

## 前提条件

- 微信开发者工具中开启**云开发模拟器**
- 准备两个微信测试号（设备 A / 设备 B），或先登录再清缓存模拟新设备
- 本地已存在一些打卡、想去、收藏数据（模拟老用户场景）

---

## 用例 1：登录流程（"我的"页面）

| # | 测试动作 | 预期结果 | 关键代码路径 |
|---|---------|---------|-------------|
| 1.1 | 打开小程序 → 进入"我的"页 | 显示未登录状态，头像和昵称为空 | `my.js` onLoad → loadUserInfo |
| 1.2 | 点击"登录"→ 同意隐私 → 授权微信信息 | 调用 `wx.cloud.callFunction({ name: 'login' })`，弹"登录中..." | `my.js` onWechatLogin |
| 1.3 | 登录成功 | 显示昵称和头像，`userInfo` 存入本地缓存 | `my.js` setData |
| 1.4 | 关闭小程序 → 重新打开 | 再次进入自动登录态，显示上次的昵称和头像 | `my.js` onLoad → loadUserInfo |
| 1.5 | 退出登录 | 本地 `userInfo` 清空，页面回到未登录状态，打卡数据保留 | `my.js` onLogout |

## 用例 3：首页数据加载（云端模式）

## 用例 8：路线管理（云端读写）

| # | 测试动作 | 预期结果 | 关键代码路径 |
|---|---------|---------|-------------|
| 8.1 | 已登录 → 进入想去页 → 切换到"路线" tab | 调用 `util.getRoutesAsync()` → 显示云端路线列表 | `wantgo.js` onShow → `getRoutesAsync` |
| 8.2 | 已登录 → 在"路线" tab 点击一条路线卡片 | 跳转到路线详情页，显示路线地图、每日行程 | `wantgo.js` onRouteCardTap → `my-route.js` |
| 8.3 | 已登录 → 在路线详情页编辑（增删地点、调序）→ 保存 | 调用 `saveRouteToStorage()` → **仅写入本地** `savedRoutes` | `my-route.js` onSave → saveRouteToStorage |
| 8.4 | 在路线详情页编辑基础信息（名称、城市）→ 保存 | 调用 `loadData/setStorageSync` → **仅写入本地** `savedRoutes` | `route-basic-edit.js` onSave |
| 8.5 | 已登录 → 在路线规划页（route.js）规划路线 → 点"保存" | 调用 `savePreviewRouteData()` → **仅写入本地** `savedRoutes` | `route.js` onSaveToMyRoute |
| 8.6 | 已登录 → 在路线列表长按路线 → 选择"删除" | 调用 `util.deleteRouteAsync(id)` → 云端删除 → 本地同步 | `wantgo.js` deleteRoute → `deleteRouteAsync` |
| 8.7 | 已登录 → 在路线编辑页（route-basic-edit）→ 删除路线 | 调用 `loadData/filter/setStorageSync` → **仅删除本地** | `route-basic-edit.js` onDeleteRoute |
| 8.8 | 已登录 → 在路线列表长按 → 选择"复制" | 调用 `getRoutesAsync()` → 复制一份（新ID）→ 保存到**本地** | `wantgo.js` copyRoute |
| 8.9 | 已登录 → 在路线列表长按 → 选择"发布为攻略" | 复制路线到 `myGuides` 并标记为攻略草稿 → **仅本地** | `wantgo.js` publishRouteAsGuide |
| 8.10 | 在**设备 A** 删除一条路线 → 设备 B 刷新 | 设备 B 的路线列表也同步删除了该路线 | 云端 `routes` 集合共享 |

## 用例 9：异常和边界情况

| # | 测试动作 | 预期结果 | 关键代码路径 |
|---|---------|---------|-------------|
| 9.1 | 断网状态下读取数据 | 云端失败 → 自动降级到本地缓存 → 数据照常显示 | 各 `xxxAsync` 函数 |
| 9.2 | 断网状态下新增数据 | 云端失败 → 降级到本地存储 → 数据保存到本地 | 各 `xxxAsync` 函数 |
| 9.3 | 登录后立即退出 → 再登录（不同账号） | 新账号数据为空 → 不显示旧账号的数据 | login → loadData |
| 9.4 | 未登录状态下云端 DAL 被误调用 | `_isCloudMode()` 返回 `false` → 直接走本地路径，不报错 | 各 `_isCloudMode` 检查 |
| 9.5 | 云函数 login 返回失败 | 弹"登录失败，请重试" toast，页面保持未登录态 | `my.js` onWechatLogin catch |

## 路线云端同步缺口

> ⚠️ **`util.js` 未实现 `saveRouteAsync` 和 `updateRouteAsync`**，路线的新增和编辑操作**仅保存在本地缓存 `savedRoutes`**，不会推送到云端。  
> 当前仅 `getRoutesAsync()`（读取）和 `deleteRouteAsync()`（删除）对接了云端 DAL。  
> 如需完整云端同步，需补充实现后两个函数，并修改 `my-route.js` 的 `saveRouteToStorage`、`route-basic-edit.js` 的 `onSave` 调用云端写入。

## 测试优先级

| 优先级 | 用例 | 原因 |
|-------|------|------|
| **P0** | 1.1 ~ 1.4（登录）, 3.1 ~ 3.4（首页想去）, 5.1 ~ 5.2（打卡） | 最核心的登录 + 数据读写链路 |
| **P1** | 2.1 ~ 2.5（数据迁移）, 6.1 ~ 6.4（收藏）, 4.1 ~ 4.3（想去页）, 8.1、8.2、8.6（路线列表/删除） | 功能性验证 |
| **P2** | 7.1 ~ 7.6（跨设备）, 9.1 ~ 9.5（异常）, 8.3 ~ 8.5、8.8、8.9（路线编辑/复制/发布） | 数据一致性和健壮性 |

> **P0 用例通过即可认为新增云端功能基本可用；P1/P2 用于验收完整性和健壮性。**
