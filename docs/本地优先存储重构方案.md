# 本地优先存储重构方案

> 目标：将"云端优先、本地兜底"改为"本地优先、云端同步"，消除所有网络等待对 UI 的影响。

---

## 一、问题现状

### 当前架构：云端优先（Cloud-First）

```
UI 操作 → await 云端 API → 成功？→ 更新本地缓存 → 返回
                              ↕ 失败
                            → 走本地兜底 → 返回
```

### 用户感知的三个痛点

| 场景 | 表现 | 原因 |
|------|------|------|
| 进入页面 | 白屏或 Loading，等云端返回才展示 | `onLoad` / `onShow` 中有 `await xxxAsync()` |
| 点"想去/收藏" | 按钮状态有延迟才翻转 | `toggleAsync` 等待云端返回后才更新本地 |
| 取消收藏后 | 列表闪烁，重新 Loading | 写操作后 `setTimeout(loadData, 500)` 再次 fetch 云端 |

---

## 二、设计原则

```
读操作：始终从本地返回（零等待），后台异步拉云端刷新缓存
写操作：先写本地（即时反馈），后台异步推云端
同步：统一由 SyncManager 调度，去重、防冲突、节流
```

### 核心转变

| 维度 | 当前 | 设计后 |
|------|------|--------|
| 数据源 | 云端是主，本地是缓存 | 本地是主，云端是同步目标 |
| 读时序 | await 云端 → 更新本地 → 返回 | 返回本地（立即）→ 后台刷新 |
| 写时序 | await 云端 → 成功才更新本地 | 立即更新本地 → 后台推送云端 |
| 离线 | 云端失败才降级 | 天然支持离线 |

---

## 三、架构分层

```
┌──────────────────────────────────────────────┐
│ Pages (UI 层)                                │
│ - 读：调用同步版函数（零等待）                 │
│ - 写：调用函数（本地即时翻转）                  │
│ - 同步完成：通过 SyncManager 监听收到通知后刷新 │
└──────────────┬───────────────────────────────┘
               │
┌──────────────▼──────────────────────────────┐
│ Facade Layer (util.js / checkinUtil.js 等)  │
│ - getXXX()：直接读本地，触发 enqueue 后台刷新 │
│ - toggleXXX()：先改本地，返回，enqueue 后台推 │
└──────────────┬──────────────────────────────┘
               │
┌──────────────▼──────────────┐
│ Local Store (同步)          │
│ wx.setStorageSync           │ ← 主数据源
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│ SyncManager (异步，独立线程) │
│ - 启动/登录时全量同步        │
│ - 每次写操作后增量同步（节流）│
│ - 冲突：云端为主            │
│ - 状态：syncing / synced /  │
│          error              │
│ - 事件通知：页面监听刷新     │
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│ Cloud DAL (utils/db/*.js)  │
│ 保持现有接口不变             │
└─────────────────────────────┘
```

## 四、核心模块设计

### 4.1 SyncManager（新增文件）

**路径：** `utils/db/syncManager.js`

```javascript
class SyncManager {
  // ── 生命周期 ──
  init()              // 启动/登录时调用，触发全量同步
  on(entity, cb)      // 页面注册监听
  off(entity, cb)     // 页面取消监听
  getStatus(entity)   // 获取同步状态

  // ── 触发同步 ──
  enqueue(entity, opts?)  // 推入同步队列（带 2s 节流）

  // ── 内部 ──
  _sync(entity)               // 执行同步
  _notify(entity, status)      // 通知监听者
  _recordPendingOp(...)        // 记录待推送操作
  _mergeLists(cloud, local, pendingOps) // 合并冲突
}
```

**同步策略表：**

| 实体 | 方向 | 冲突策略 | 触发时机 |
|------|------|---------|---------|
| checkinRecords | 双向 | 云端优先（本地是降级写缓存） | 启动 + 每次写后 |
| wantList | 云端→本地 | 云端覆盖 | 启动 + 写后推送 |
| collectedList | 云端→本地 | 云端覆盖 | 启动 + 写后推送 |
| userAddedShops | 双向 | 有 _id 的云端为准，无 _id 的推送 | 启动 + 写后 |
| routes | 双向 | 同上 | 启动 + 写后 |

**节流规则：** 同一实体两次同步间隔 >= 2 秒，高频操作只触发一次。

### 4.2 各实体的 Facade 层改造

以 `wantList` 为例，改造前后的对比：

**改造前（云端优先）：**
```javascript
async function getWantListAsync() {
  if (!_isCloudMode()) return getWantList()
  const { success, data } = await _getDbWantList().getList()
  if (success) {
    saveData('userWantList', data)
    return data
  }
  return getWantList()
}

async function toggleWantAsync(id, placeType = 'food') {
  const strId = String(id)
  if (!_isCloudMode()) { return toggleLocal(id) }
  const { success, data } = await _getDbWantList().toggle(strId, placeType)
  if (success) {
    // 同步本地缓存
    const list = getWantList()
    if (data) { if (!list.includes(strId)) list.push(strId) }
    else      { const idx = list.indexOf(strId); if (idx > -1) list.splice(idx, 1) }
    saveData('userWantList', list)
    return data
  }
  return toggleLocal(id)
}
```

**改造后（本地优先）：**
```javascript
// —— 读取（本地即时 + 后台刷新）——
function getWantList() {
  const list = loadData('userWantList', [])
  // 已登录时，后台触发同步
  if (_isCloudMode()) {
    syncManager.enqueue('wantList')
  }
  return list.map(v => String(v))
}

// —— 写入（本地先改 + 后台推送）——
async function toggleWantAsync(id, placeType = 'food') {
  const strId = String(id)
  // Step 1: 立即改本地
  const list = getWantList()
  const idx = list.indexOf(strId)
  let isWantNow
  if (idx > -1) { list.splice(idx, 1); isWantNow = false }
  else         { list.push(strId); isWantNow = true }
  saveData('userWantList', list)

  // Step 2: 后台推云端
  if (_isCloudMode()) {
    syncManager.enqueue('wantList', { pendingOp: { type: 'toggle', id: strId, placeType } })
  }

  return isWantNow
}
```

### 4.3 页面层改造规范

**通用模板：**

```javascript
Page({
  onLoad() {
    // 1. 注册同步完成监听（用于后台自动刷新）
    syncManager.on('wantList', () => this.loadData())
    syncManager.on('checkinRecords', () => this.loadCheckinStats())
    // 2. 立即加载本地数据
    this.loadData()
  },

  onUnload() {
    syncManager.off('wantList')
    syncManager.off('checkinRecords')
  },

  onShow() {
    // 只重新加载本地数据（零等待）
    this.loadData()
  },

  // 数据加载方法，只读本地
  loadData() {
    const list = util.getWantList()  // 同步，零等待
    this.setData({ ... })
  },

  // 写操作
  onToggleWant(e) {
    const id = e.currentTarget.dataset.id
    util.toggleWantAsync(id, 'food')   // 立即翻转本地
    this.loadData()                    // 重新渲染
    // 无需 await，无需 setTimeout
  }
})
```

## 六、迁移风险与应对

| 风险 | 应对 |
|------|------|
| 写后立即读，云端未同步 | 读本地缓存，本地已有最新数据，无问题 |
| 多设备同时写导致冲突 | wantList/collectedList 以云端为准（`toggle` 原子操作） |
| checkinRecords 双向冲突 | 每条记录有独立 _id，云端写入后返回 _id 更新本地 |
| 同步失败静默丢操作 | SyncManager 记录 pendingOps，下次重试 |
| 用户登出后本地数据残留 | 登出时不清 checkin_records，只清 userInfo |
